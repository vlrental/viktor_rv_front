### 0.1 Git

### 0.3 CSS
- CSS — обычные файлы: `assets/main.css` + `assets/css/<страница>.css`. Сборки НЕТ (нет npm/tailwind).
- Правишь стиль — правишь прямо в этих `.css`; подключение через `asset!()` / `document::Stylesheet` в Rust.
- Цвета — через CSS-переменные (единый источник), а не хардкод-хексы вразнобой. Не использовать чистый

### 0.4 Supabase / SQL (000.SQL.SUPABASE)
- Изменение схемы БД ассистент выполняет САМ через Supabase MCP (когда он авторизован), не оставляет юзеру.
- Порядок: идемпотентный DDL в коде/миграции → тот же DDL в Supabase через MCP → проверить `select`
  из `information_schema`.
- DDL — только идемпотентный (`IF NOT EXISTS`). Деструктив (DROP, массовый UPDATE/DELETE) — только по команде.
- MCP не авторизован — сказать явно (нужен `/mcp` в интерактиве), SQL продублировать блоком в ответе.
- Секреты/ключи Supabase — только в бэкенд/env, НИКОГДА в фронт-WASM и не выводить в чат.

### 3.1 Мёртвый код — сносить сразу (000.DEAD.CODE)
Мёртвое (grep по `src/` — ноль ссылок кроме определения и `pub use`) удалять БЕЗ запроса: файл + `mod`
+ все `pub use` в той же задаче. Перед удалением проверить: не используется ли в другой `#[cfg]`-ветке
или за feature — cfg-gated код НЕ мёртвый; `#[allow(dead_code)]` с причиной не трогать. После —
`cargo check` без новых ошибок/warnings. Живые фичи/анимации — только по явной команде.

### 3.2 Зелёный билд — крайне строго (000.BUILD.GREEN)
**Красный билд — НИКОГДА не конечное состояние хода.** Тронул код → перед «готово» он собирается
зелёным (`cargo check`).
- Ломающее изменение (новое поле struct / вариант enum / смена сигнатуры / переименование) —
  атомарно, в ОДНОЙ задаче со ВСЕМИ сайтами использования до зелёного.
- Провал `Edit` = правка НЕ применилась → переделать сразу, подтвердить финальным `cargo check`.
- «Не уверен, что зелёный» = красный. «Готово» — только после реально прогнанного билда.

### 3.3 Ошибки — ВСЕГДА наружу (000.ERROR.SURFACE)
- Не прятать причину за generic `500`/«Не удалось …». Результат КАЖДОГО сетевого/`Result`-вызова
  обрабатывать, ошибку показывать осмысленно; диагностический контекст — в лог.
- Backend (Supabase/edge): ожидаемый сбой → понятный код ошибки, не «Internal»; реальную деталь —
  в server-лог, не в клиент (без stack/SQL/секретов/путей).
- Паника/500 = БАГ, чинить в корне, не маскировать ретраем.

## 4. АРХИТЕКТУРА (лёгкая)
Проект простой, но разделение слоёв держать:
- UI (`src/pages`, `src/components`) не дёргает сеть/HTTP/Supabase напрямую — через слой данных
  (`src/data.rs` и будущие сервисы/порты). Даже для hotfix.
- State — по сущностям; шаренный — через context (`use_context_provider` в родителе, `use_context` в детях).
- Зависимости — инъекцией (`Arc<dyn Trait>`), не `let client = X::new()` внутри метода.

### 4.1 Props — без prop drilling
Props — только display-данные (`String`, `bool`, `i32`, готовые модели). Сигналы, State, `Arc<dyn ...>`
— НЕ тащить пропами через уровни, а раздавать через context: `#[derive(Clone, Copy)]`-struct с
Signal-полями. Родитель, читающий сигнал и передающий значение-копию (`Child { value: count() }`),
перерендеривается целиком → передавать сам Signal (`Child { count }`).

## 5. DIOXUS 0.7.9 — ПРАВИЛА И АНТИПАТТЕРНЫ

### 5.1 Чеклист перед правкой UI/state/hooks
1. Hooks безусловно и в одном порядке (не в `if`/`match`/циклах/обработчиках, до любых `return`).
2. Render без side effects — `signal.set()` в теле компонента = бесконечный цикл.
3. Правильный инструмент: `use_signal` — локальный стейт; `use_memo` — синхронное производное;
   `use_resource`/`spawn` — async; `use_effect` — синхронизация с внешним миром.
4. Shared state через context/provider.
5. Cleanup обязателен — listeners, таймеры через `use_drop`.
6. Списки — стабильный `key` по business-id, не индекс.

### 5.2 Жёсткие запреты (проектные, выученные в idyll)
```
❌ use_effect → set() для derived-значений — двойной рендер / убивает WASM UI thread (→ use_memo)
❌ signal.read() + signal.set() одного сигнала в одном effect — self-trigger, бесконечный цикл
❌ std::time::Instant::now() на wasm32 — panic
❌ chrono::Local::now() на WASM — возвращает UTC (не локаль!)
❌ web_sys без #[cfg(target_arch = "wasm32")]
❌ use_navigator() вне Router-контекста
❌ _-префикс на props Dioxus-компонентов (ломает props builder)
❌ let внутри rsx!{} ; #[cfg(...)] внутри rsx!{}
❌ Signal.set() без mut
❌ Inline style = String::new() при переключении состояний — CSS «залипает»
❌ Shorthand `background:` в условном инлайн-стиле toggle-кнопки — 0.7.9 не патчит его при тоггле,
   активная заливка ПРОПАДАЕТ. Только `background-color:` longhand (§5.4)
❌ use_memo с .read() внутри — RefCell panic при hot-reload (читать через peek() или зависимость снаружи)
❌ Кэш-геттер, читающий сигнал (.read()) внутри use_effect, + запись в тот же сигнал после fetch —
   скрытая подписка → бесконечный запрос-цикл. Кэш-геттеры/RMW в State — только peek()
```

### 5.3 Даты и время (на WASM)
- `std::time::Instant::now()` и `chrono::Local::now()` на wasm — НЕЛЬЗЯ (паника / UTC вместо локали).
- Календарная дата/время — `chrono::Utc::now()` + конвертация в локаль на показ; на сервер — UTC с `Z`.
- Длительность/elapsed — через `performance.now()` (мс-точность), не через разницу локальных времён.
- WASM-логирование: `web_sys::console::log_1(&"msg".into())` — `log::info!` в браузере не виден.

### 5.4 Inline style — явный сброс + ТОЛЬКО longhand
```rust
// ПЛОХО — залипает / пропадает заливка:
style: if active { "background: red;" } else { String::new() },
// ХОРОШО — все свойства явно в ОБЕИХ ветках, заливка через LONGHAND:
style: if active { "background-color: red; box-shadow: ...;" }
       else       { "background-color: transparent; box-shadow: none;" },
```
В условном инлайн-стиле НИКОГДА shorthand `background:`/`border:` — только `background-color:`,
`border-color:`/`border-width:`. 0.7.9 per-property диф патчит longhand, но shorthand `background` при
тоггле НЕ патчит (текст перекрасился — заливка пропала). Значения comma-free.

### 5.5 Ключи
В списках — стабильный `key` по business-id, БЕЗ state (state в key = churn, подсветка прыгает).
Индекс как key — только если ряд НЕ переупорядочивается.

### 5.6 Hot-reload паники
`RefCell already borrowed`, `index out of bounds` при hot-reload — баги Dioxus, не твой код.
Решение: F5 в браузере → при необходимости перезапустить `dx serve` (`make k` + `make c`).

### 5.7 Справочник антипаттернов (АП-1…АП-33)
> Не полагаться на «я и так знаю» — эти грабли ловились многократно.

**use_effect:**
- **АП-1** Derived через `use_effect`+`set()` → `use_memo` (`use_memo(move || data().into_iter().filter(...).collect())`).
- **АП-2** `signal()` (read) + `signal.set()` в одном эффекте = бесконечный цикл → читать `*sig.peek()` или логику в обработчик.
- **АП-3** `.set()` в теле компонента = infinite rerender. Однократная инициализация → `use_hook`; реактивно → `use_effect`.
- **АП-4** Цепочка map/filter/sort в одном effect с несколькими `set()` → каждый шаг = свой `use_memo`.
- **АП-5** Effect + сигнал-флаг вместо обработчика → вызывать логику прямо из `onclick`.
- **АП-6** Зеркалирование сигнала (`mirror.set(source())`) → использовать source напрямую (Signal = Copy).
- **АП-7** Блокирующий код в effect (`std::thread::sleep`) → `tokio::time::sleep().await`; CPU-тяжёлое → `spawn_blocking`.
- **АП-8** Не дробить связанную логику на россыпь мелких effect без причины.
- **АП-9** Non-signal проп (String/u32) в effect НЕ реактивен → `use_effect(use_reactive((&word,), |(word,)| …))` или `ReadSignal<T>`.

**use_memo:**
- **АП-10** Side-effect внутри memo запрещён (может не пересчитаться по PartialEq) → в `use_effect`.
- **АП-11** memo без сигнальных зависимостей бессмыслен → `use_hook`/const.
- **АП-12** Цепочка memo для дешёвой арифметики → один memo; memo только для дорогого.
- **АП-13** memo ради «наблюдения» с логом → `use_effect`.

**use_resource / use_future:**
- **АП-14** `use_future` — один раз при маунте, не реактивен. Реактивный запрос → `use_resource`.
- **АП-15** `use_resource` + non-signal проп → не перезапустится → `use_reactive`/`ReadSignal`-проп.
- **АП-16** Lock через `.await` (`let d = items.read(); fetch().await`) = дедлок → клонировать ДО await.
- **АП-17** `data.read().unwrap()` до завершения Future = паника → `match &*data.read() { Some/None }`.

**Сигналы и стейт:**
- **АП-18** `RefCell`/`Mutex` в props — запись не уведомляет Dioxus → `Signal<T>`.
- **АП-19** `write_silent()` глушит всех подписчиков → для обхода цикла `peek()` на чтение + обычный `write()`.
- **АП-20** `GlobalSignal` для локального стейта → `use_signal`; global только для сквозного (тема, юзер).
- **АП-21** Родитель передаёт значение-копию (`Child { value: count() }`) → перерендер родителя → передавать Signal.
- **АП-22** Derived как отдельный сигнал (`items_count`) → рассинхрон; `use_memo` от источника истины.

**Props и компоненты:**
- **АП-23** Ручной `PartialEq` всегда `true` = компонент не получит новые props → `derive(PartialEq)`.
- **АП-24** Нет ключей / индекс-ключ → перепутанные состояния при удалении → `li { key: "{item.id}" }`.
- **АП-25** Недетерминизм в теле (`rand::random()` на рендер) → `use_hook`.
- **АП-26** Обновление стейта в render-path → бесконечный цикл; мутации только в обработчиках/эффектах.

**Async и spawn:**
- **АП-27** `spawn(async { signal() })` без `move` не компилится → `async move` (Signal = Copy).
- **АП-28** Non-Copy (String) в несколько задач → клонировать перед move; лучше `ReadSignal<T>`.
- **АП-29** `tokio::spawn` + `Signal` (не Send) → `use_signal_sync` или dioxus `spawn` (main thread).
- **АП-30** Фоновая задача на всё приложение — `spawn_forever` в root; `spawn` в компоненте умрёт с ним.

**Правила хуков:**
- **АП-31/32/33** Хук в `if`/`match`/цикле, в обработчике, после early return — паника/сломанный порядок.
  ВСЕ хуки — безусловно, в корне компонента, ДО любых `return`.

### 5.8 Шпаргалка: когда что использовать
| Задача | Инструмент |
|---|---|
| Производное значение из сигналов | `use_memo` |
| Side-effect (DOM, logging, storage) | `use_effect` |
| Реактивный async-запрос | `use_resource` |
| Однократный async при маунте | `use_future` |
| Долгоживущий event loop | `use_coroutine` |
| Однократное вычисление при маунте | `use_hook` |
| Локальный стейт | `use_signal` |
| Шаренный стейт | `use_context_provider` + `use_context` |
| Глобальный стейт приложения | `GlobalSignal` |
| Non-signal зависимость в эффекте/ресурсе | `use_reactive((&dep,), \|_\| ...)` |
| Фоновая задача на всё приложение | `spawn_forever` |

### 5.9 Быстрые признаки антипаттерна
| Видишь | Проблема |
|---|---|
| `use_effect` + `.set(derived)` | → `use_memo` |
| `signal()` и `signal.set()` в одном `use_effect` | → бесконечный цикл, `peek()` |
| `.set(...)` в теле компонента | → бесконечный цикл |
| `use_future` + чтение сигнала | → `use_resource` |
| `use_resource` + String/u32 проп без `use_reactive` | → не перезапустится |
| `std::thread::sleep` в `use_effect` | → `tokio::time::sleep().await` |
| Lock (`.read()`) через `.await` | → клонировать до await |
| Хук внутри `if`, `match`, `for` | → паника в рантайме |
| `RefCell`/`Mutex` в props | → `Signal<T>` |
| `PartialEq` всегда `true` | → компонент не обновится |
| Индекс как `key` | → баги при перестановке |
| `addEventListener` без cleanup | → `use_drop` + `removeEventListener` |
| Условный инлайн-`background:` (shorthand) на toggle | → заливка пропадает; `background-color:` longhand |

## 6. UI

### 6.1 Текст и контраст
- Цвет текста — через CSS-переменную темы (`var(--...text)`), не хардкод `white`/`black`/цвет-фона.
- На цветной заливке — контрастный текст (светлый на тёмном, тёмный на светлом), проверять читаемость.
- Подписи/вторичный текст — тем же цветом текста с `opacity`, не отдельным серым хексом.

### 6.2 Запреты UI
```
❌❌ ТОЛСТЫЕ БЕЛЫЕ/СВЕТЛЫЕ БОРДЕРЫ на кнопках/пилюлях/карточках (частый дизайн-баг)
❌ Тонкие высококонтрастные hairline-бордеры на тёмном фоне
❌ «Резиновые» floating-элементы с transition на top/left
❌ transition: all на пилюлях/кнопках (анимирует border-color и застревает на ярком active)
```
Поверхность stateful-кнопок — заливкой (`background-color`, `border: none`). Нужна граница —
`var(--...border)` или мягкая тень `0 2px 6px rgba(0,0,0,.2)`, НЕ белый бордер.

### 6.3 Кнопки/пилюли — канон (Dioxus 0.7.9)
Любая кнопка/пилюля, чей вид зависит от state, — пройти по порядку СРАЗУ при написании
(и диагностику «кнопка поломана» вести в этом же порядке — структура чаще корень, чем ключ):

- **Структура.** keyed-`for` пилюль НЕЛЬЗЯ держать в одном родителе с некейным сиблингом (заголовок/
  иконка/label) — смешение ломает реконсиляцию: заливка не применяется/рамка залипает. Метку выносить
  наружу, keyed-`for` — в свой `div`.
- **Ключи (компонент-пилюля с условным инлайн-`style:`).** Диф стиля корня компонента 0.7.9 не
  перетирает → лечит call-site remount-key со state: в `for`-ряду суффикс = ВЫБРАННОЕ значение ряда,
  одинаковое для всех (`key: "type-{i}-{cur}"`) — ряд ремоунтится целиком. НЕ per-pill bool (`{active}`)
  — частичное переиспользование = churn (подсветка прыгает на чужую пилюлю).
- **Сырой `button` в `for`** — in-place диф работает: стабильный key + §5.4 достаточно (запасной пуленепробиваемый паттерн).
- **§5.4 — явный стиль в ОБЕИХ ветках**, БЕЗ `transition: all`, только longhand `background-color:`.
- **Цвет выбора.** Active-заливка — акцент, контрастный фону; idle — нейтральная поверхность. Контраст idle↔active большой.
- **Контраст/тени.** Текст/иконка на насыщенной заливке — контрастный цвет; на мелкой кнопке (≤44px)
  цветной halo-shadow выглядит «поломанной рамкой» → нейтральная тень.

Перед «готово» по кнопке — grep стиля на `border` (светлый убрать) и на shorthand `background:`.

### 6.4 Поверхности — сплошные
- Фон карточки/чипа/плитки/поля = сплошная заливка (`var(--...card)` или `color-mix(... var(--...card))`).
  ЗАПРЕЩЕНО `color-mix(..., transparent)` как ФОН поверхности (просвечивает фон страницы = «дырка»).
- Бордеры сплошные через `var(--...border)`.
- Легитимный transparent: цвет текста/тени, фон кнопки/инпута ПОВЕРХ уже сплошной поверхности, общая полупрозрачная подложка-панель.

### 6.5 z-index и stacking-context trap
- z-index держать по единой лестнице (фон → контент → навбар → модалки → критические оверлеи), не хардкодить случайные `z-[NNN]`.
- **⚠️ Главная ловушка:** `position: fixed` внутри предка с `transform`/`filter`/`contain:paint`/
  `will-change` привязывается к ЭТОМУ предку — модалка съезжает и уходит под навбар, сколько ни ставь
  z-index. Лечение: оверлей поверх всего рендерить на КОРНЕ приложения (рядом с root-оверлеями), состояние — сигналом, не инлайн в карточке.

### 6.6 Иконки без декора
Иконка — голый глиф (тонируется цветом), БЕЗ фоновой заливки/бордера/капсулы/тени вокруг, в т.ч. в
кнопках-селекторах (кнопка прозрачная, внутри голая иконка). Исключение — функциональная мини-КНОПКА,
где цветной кружок = фон всего tap-таргета. Тест: убери «фон» мысленно — исчез tap-таргет → легитимно;
осталась кликабельная карточка → запрещённый декор. SVG: CSS-переменные в `stroke`/`fill` не работают — задавать через `style:`.

### 6.7 Оверлеи: не за экран + закрытие тапом
- Любой попап/пикер, позиционируемый от триггера, — проверять вылет за viewport по реальной геометрии
  (не «на глаз»): у нижнего края открывать вверх; якорить к ближнему краю триггера, не к центру.
- Каждый оверлей закрывается тапом по пустому месту (клик по бэкдропу или document-листенер) и повторным
  тапом по триггеру. Тап по самому оверлею не закрывает (`stop_propagation`). Fixed-бэкдроп внутри
  transform-поддерева не работает (та же ловушка §6.5) — вешать листенер на document.

### 6.8 Мелочи UI
- Autosave — тихо: никаких `saving…`/`saved`-тостов, UI меняется только при ошибке.
- «Скролл не доходит, кнопки перекрывают контент» → `padding-bottom` на скроллируемом контейнере, не трогать padding-right.
- Данные юзера (цифры, имена, суммы) — выделяемы; `user-select: none` только на интерактиве (кнопки/жест-зоны).

## 8. WINDOWS / СБОРКА

### 8.1 000.PS.ASCII — PowerShell-скрипты только ASCII
`.ps1` без кириллицы/юникода (em-dash «—» тоже нельзя): PowerShell 5.1 читает файл без BOM как ANSI →
мойибейк ломает парсинг. Комментарии в `.ps1` — на английском ASCII.

### 8.2 `key` только на ПЕРВОМ узле блока
`key:` работает лишь на первом узле rsx-блока (диффинг списков); на обычных stateful-кнопках
игнорируется + deprecation-warning. Залипание инлайн-стилей лечить через §5.4/§6.3, НЕ через key.
Мёртвые `let *_key = format!(...)` — удалять.

### 8.3 000.BUILD.NO_WARN — без warnings
Новый/тронутый код — без warnings. Частые: лишний `mut` на сигнале (мутация в замыкании через копию —
убрать внешний `mut`); `unused variable` в wasm-ветке (сослаться `let _ = (&x,);` в парном
`#[cfg(not(wasm32))]`, НЕ `_`-префикс); `unused import` под мёртвым `key:`. Warning, всплывший в реальной
сборке (`dx build`/`cargo check`), гасить сразу в той же задаче, даже если старый и не твой. Не `_`-затыкать.
